# 島旅フェリー予約 — 共通フェリー予約プロトタイプ

GitHub Pagesでは `.github/workflows/pages.yml` が `dist` を自動公開します。

伊平屋島・伊是名島の2航路を共通UIで扱う、モバイル優先の操作可能プロトタイプです。すべてデモであり、本物の決済・予約登録・個人情報保存・メール送信は行いません。

## 実装画面

- 利用者画面（`#user`）：島選択トップ、海・雲・波・フェリまるのアニメーション
- 本日の運航状況／今日のフェリー運航イメージ
- 8ステップ予約フロー（往復、日付、便、人数、乗船者、確認、デモ決済、完了）
- QR乗船券、便変更、キャンセル
- 職員管理画面（`#admin`）：専用ヘッダー、権限表示、全航路／伊平屋／伊是名の切替
- 管理ダッシュボード：本日の予約、乗船予定、売上、運航状況、便別人数、最近の予約

プロトタイプではURLフラグで分離しています。本番では管理画面を認証・職員権限で保護し、一般利用者からアクセスできない別ルートまたは別サブドメインとして配備します。

## UIデザイン

- 実写調の沖縄の海と白いフェリーを主役にした旅行サービス風ヒーロー
- 白いカード、濃いブルーの主要ボタン、緑の運航ステータスを基調とした構成
- PCでは横長の島選択パネル、スマートフォンでは写真付きリストへ切り替わるレスポンシブ設計
- 予約画面は1ステップ1タスクで、参考イメージに近い細い進捗バーとカード選択UI
- ヒーロー画像は画像生成機能で作成したプロジェクト専用素材（`dist/assets/okinawa-ferry-hero.png`）

## 運航情報の取得

`src/services/ferryStatusService.js` に `FerryStatusService` を定義し、`getIheyaStatus()` と `getIzenaStatus()` を同じ `getStatus(routeId)` に集約しています。本番ではブラウザから村公式サイトへ直接アクセスせず、`/api/ferry-status` のサーバー側アダプターから正規化済みJSONを取得します。サーバー側で公式発表を取得・検証し、失敗時はUIに取得失敗と公式リンクを表示する想定です。

## デモ／実データ切替

```js
new FerryStatusService({ mode: 'demo' })
new FerryStatusService({ mode: 'live', endpoint: '/api/ferry-status' })
```

現在の配信版は完全静的なため、画面表示は `dist/app.js` の航路マスタ内デモデータを使用します。

## 本番化に必要な作業

1. 伊平屋村・伊是名村とデータ利用／取得頻度／障害時表示を合意する
2. サーバー側fetchまたはスクレイパーアダプターを実装し、DOM変更監視とキャッシュを設ける
3. 正式な時刻・運賃・空席・運休ルールを航路マスタへ接続する
4. 認証、予約在庫の排他制御、決済事業者、取消・払戻、通知を実装する
5. 個人情報保護、監査ログ、アクセシビリティ、セキュリティ、負荷・災害時試験を行う
6. QR署名・改ざん防止と港での読取／オフライン運用を整備する
